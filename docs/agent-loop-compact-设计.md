# Agent Loop 上下文压缩设计

## 目标

为 demo 提供基础上下文压缩机制。阈值用于便于演示，不代表生产环境的真实模型 token 限制。

## 触发与估算

- 以字符数除以 4 估算上下文 token 数。
- 模型请求前检查上下文；估算 token 数达到 18k 时触发压缩。该阈值为 20k 上限预留约 2k token 安全空间。
- 摘要请求计入每个 Run 最多 64 次模型请求的限制。

## 压缩范围与顺序

- 保留 system prompt、工具注册参数及最近约 4k token 的完整对话轮次。
- 用户消息（包括已应用的 steering 消息）参与近期消息的预算统计和截取，保留部分保持原始消息顺序；最新用户输入必须完整保留，即使因此超出约 4k token 的保留预算。
- Turn 包含该次模型响应及其触发的完整工具调用和工具结果；压缩不得拆开工具调用链。
- 从最近的 Turn 向前保留，直到达到约 4k token。若单个 Turn 自身超出预算，完整保留该 Turn。
- 更早的消息由模型整理为结构化摘要。压缩后的模型上下文顺序为：system prompt、压缩摘要、保留的近期会话消息。工具注册信息通过独立的 `tools` 参数传入，不属于 `messages`。
- 后续压缩时，将已有摘要与新覆盖的历史一并纳入摘要输入，避免摘要被覆盖或历史信息丢失。

## 摘要结构

摘要使用 JSON 对象，包含以下字段：

```json
{
  "current_goal": "当前目标",
  "user_preferences": [],
  "task_progress": "当前任务进度",
  "completed_tasks": [],
  "next_tasks": [],
  "decisions": [],
  "relevant_facts": [],
  "open_questions": []
}
```

摘要提示词要求：仅记录原始对话明确支持且对后续任务有用的信息；保留关键约束、用户偏好、已作决策、任务状态和未解决问题；不推测、不补造信息；未知字段使用空字符串或空数组；严格输出符合结构的 JSON，不附加 Markdown 或解释。

## 持久化与失败处理

- 摘要请求以 `compact.request` 单独记录，成功后以 `compact.completed` 保存结构化摘要、累计覆盖的消息 ID 和前一压缩记录 ID；不作为业务回答流输出。后续重建上下文时以摘要替代被覆盖的消息，近期消息保持原顺序。
- 压缩记录需能识别其覆盖范围，防止重复压缩及误删未覆盖消息。
- 摘要遵循来源 Run 的上下文可见性：当前 Run 内可使用其摘要；Run 以 `failed`、`stopped`、`limited` 或 `interrupted` 结束后，其消息及包含这些消息的摘要均不进入后续 Run 的 context。该摘要覆盖的已完成历史在后续 Run 中仍使用此前有效的摘要或原始消息重建。
- 摘要生成或结构校验失败时，Run 以 `failed` 结束；不丢弃原始消息，不写入无效压缩记录。
- 压缩后重新估算 system prompt、摘要、保留消息和工具注册参数的总 token 数；仍超过 20k 或无可压缩历史且超过 20k 时，Run 以 `failed` 结束，不继续请求业务模型，也不反复压缩。
- 压缩期间收到停止信号时，遵循现有协作式停止规则，不启动新的模型请求。

## 范围

Token 估算采用字符数除以 4，轮次保留采用约 4k token 预算。该实现面向 demo，后续接入真实模型时可替换为模型 tokenizer 与模型上下文限制配置。
