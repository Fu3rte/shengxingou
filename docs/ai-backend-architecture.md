## 编排原则

在 `backend/src/` 下并列放置 `ai/` 与 `app/`。`ai/` 负责 Agent 运行，`app/` 负责业务规则和 HTTP 接入。

AI 工具通过应用服务访问业务能力。启动入口负责组装依赖。

## AI 目录

- `ai/agent/loop.py`：执行模型请求、工具调用和下一轮判断。
- `ai/agent/types.py`：定义消息、工具调用、运行状态和事件。
- `ai/agent/tools.py`：注册工具，校验参数并调度执行。
- `ai/models/`：放置模型客户端及供应商协议适配。
- `ai/tools/`：放置面向 Agent 的工具定义与实现。

以上是职责规划。具体模型 SDK 和工具集合尚待确定。

## DDD 应用目录

- `app/domain/`：领域对象、领域规则和领域服务。
- `app/application/`：业务用例，以及启动 Agent 的应用服务。
- `app/infrastructure/`：数据库、外部业务服务和存储适配。
- `app/interfaces/`：FastAPI 路由、请求响应和事件传输。
- `app/main.py`：创建 FastAPI 应用并组装模型、工具与服务。

现有 `backend/src/` 已有四个 DDD 分层目录。上面是建议结构，尚未迁移目录。

## 一次请求的路径

1. FastAPI 路由接收用户输入并调用应用服务。
2. 应用服务准备本次运行的上下文与可用工具。
3. Agent Loop 通过模型适配器发起请求。
4. Loop 收到完整工具调用后，通过工具注册表执行。
5. 业务工具调用应用服务，应用服务再操作领域对象与基础设施。
6. 工具结果进入下一轮模型上下文；运行事件交给接口层传输。

请求是否支持流式传输和存储恢复，需要结合产品需求确定。

## 依赖方向

- 接口层依赖应用服务。
- 应用服务依赖领域规则及所需接口。
- 业务工具调用应用服务提供的业务能力。
- Agent Loop 依赖模型与工具契约，由入口注入具体实现。
- 领域层保持独立，不导入 FastAPI、模型 SDK 或 Agent Loop。

服务端负责注入身份与权限上下文。模型提供的工具参数只包含任务数据。

## 测试位置

- `backend/tests/ai/`：覆盖 Loop、模型适配和工具调度。
- `backend/tests/app/`：覆盖领域规则、应用服务和接口。
- 跨模块用例：覆盖一次请求中的模型响应、工具调用和结果回填。

当前尚未实现运行时，也未运行这些测试。

## 与 Pi 的对应关系

`ai/models/` 对应 Pi 的 `packages/ai/` 职责。`ai/agent/` 对应 `packages/agent/` 的运行职责。`app/` 承担本项目的服务和业务编排。Pi 的编码工具、会话系统和 durable 机制按实际需求取舍。

模型供应商、业务工具、存储方式和事件协议尚未确定。确定这些输入后再细分适配文件。
