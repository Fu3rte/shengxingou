# Agent 工具设计

## 工具定义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | `str` | 工具名称，用于模型调用和注册表查找 |
| `description` | `str` | 提供给模型的工具说明 |
| `parameters` | `type[BaseModel]` | Pydantic 参数模型 |
| `execute` | 同步函数 | 接收校验后的参数模型实例，返回字符串 |

工具注册表使用 `name` 到工具定义的映射。当前 Agent Loop 注册并启用计算器、天气和搜索；同时提供接收 `TodoList` 实例的完整注册表构造方式，在独立实例中验证四种工具。待办待 Session 持久化和删除确认实现后接入 Agent Loop，不使用进程级共享待办实例。

注册时检查名称唯一性；重复名称直接报错。天气和搜索使用可自定义的 mock 数据，工具描述及结果标明数据来源和非实时性质。

模型所需的 function 声明由工具定义生成：`name`、`description` 和 `parameters.model_json_schema()`。参数在执行前使用同一个 Pydantic 模型校验；工具可以执行额外的业务规则校验。

现有工具接口均改为接收校验后的参数模型。待办工具使用 `TodoList.execute(command)` 实例方法，接收 `TodoCommand`；接口改造阶段保留实例内存、锁和实例隔离。

Agent Loop 接入待办时，数据按 Session 隔离，同一 Session 的各次 Run 共享。待办成功操作的 `tool.completed` 事件是唯一持久记录，保存在该 Session 的 JSONL 文件中。重新打开会话或重启服务时，根据全部已记录的待办成功事件重建清单和递增 ID，不重新执行工具；所属 Run 停止、失败或中断时，已记录的操作仍保留。

待办修改的 `tool.completed` 事件持久化后，才可推送成功事件或追加 `toolResult`。安全检查或写入失败时终止 Run，未提交的内存修改不得用于后续运行；会话须根据持久记录重建后才能继续使用。JSONL 损坏时按会话损坏规则停止读取。用户手动重复提交请求可能重复添加待办。

## 调用流程

1. 循环检查停止信号，记录 `tool.started`，包含调用 ID、名称和原始参数。
2. 根据 `name` 在注册表中查找工具。
3. 使用 `parameters.model_validate_json(arguments)` 校验原始 JSON 参数。
4. 待办删除操作执行前暂停 Run，展示任务 ID 和内容，等待用户确认。
5. 将参数模型实例传给同步 `execute`，取得字符串结果。
6. 记录 `tool.completed`，并追加包含调用 ID 和结果的 `toolResult`。

多个工具按顺序执行。工具函数只接收参数模型实例；调用 ID、停止信号和执行事件由循环管理。

## 错误与停止

未知工具、无效参数、非字符串返回值和工具异常直接终止 Run，并记录失败状态。失败的工具不生成成功的 `tool.completed` 或 `toolResult`。

删除确认通过后继续执行。用户拒绝或停止时，删除不执行，Run 以 `stopped` 结束；此前已完成的工具操作保留。等待确认时服务重启，Run 按既定规则标记为 `interrupted`。确认请求和用户选择写入执行事件并通过 SSE 推送。

停止信号生效后，不再启动新工具。已经开始的同步工具可以继续到返回；执行完成后记录实际结果，再停止 Run。

工具调用和结果可能包含敏感数据。参数在执行及记录前检查已配置密钥；结果在记录或推送前检查。检测到已配置密钥的明文时拒绝相关内容并终止 Run，错误记录不包含密钥。API key 和环境变量不写入记录；明文匹配无法识别未知或变形的秘密。
